# チェックリスト: リリース前（G3）

**初回公開時は全項目**、以降のリリースでは**変更が触れた項目**を通す。

各項目の末尾は出典ID。
**[01-definition-of-done.md](../01-definition-of-done.md) G3 の MUST は、漏れなくこのリストに現れること。**
逆は不要 ── このリストにしかない項目（SEC-05、SEC-42、SEC-60 等）は出典IDで規則本体に紐づいていればよい。
DoD の MUST を変更したら、同じPRでこのリストも更新すること（[README.md](../README.md) メンテナンス節）。

無印は MUST。SHOULD の項目には明示的に `(SHOULD)` と書く。

- [ ] E2E のクリティカルパスがステージング相当環境で通る〔G3〕
- [ ] Lighthouse（モバイル、**3回実行の中央値**）: **LCP ≤ 2.5s**〔PERF-01〕

## セキュリティ — 本番設定（A02）

- [ ] `NODE_ENV=production`、デバッグ / 詳細エラー表示が無効〔SEC-90〕
- [ ] HTTPS 強制、HSTS 有効〔SEC-91〕
- [ ] `Content-Security-Policy` 設定済み（`unsafe-inline` を避けている）〔SEC-92〕
- [ ] `Strict-Transport-Security: max-age=63072000; includeSubDomains`〔SEC-92〕
- [ ] `X-Content-Type-Options: nosniff`〔SEC-92〕
- [ ] `Referrer-Policy: strict-origin-when-cross-origin`〔SEC-92〕
- [ ] `frame-ancestors 'none'`（または `X-Frame-Options: DENY`）〔SEC-92〕
- [ ] **`Permissions-Policy`**（使わない機能を無効化）〔SEC-92〕
- [ ] CORS が `*` でない〔SEC-93〕
- [ ] 認証Cookieが `HttpOnly` + `Secure` + `SameSite=Lax`〔SEC-94〕
- [ ] 本番DBの接続ユーザーが最小権限（DDL権限を持たない）〔SEC-95〕
- [ ] ストレージの公開バケットに非公開ファイルがない〔SEC-96〕
- [ ] 管理画面 / シードデータ / テストアカウントが本番に存在しない〔SEC-97〕
- [ ] `/.env`、`/.git`、ソースマップが公開されていない〔SEC-98〕

## セキュリティ — シークレット（A02）

- [ ] `.env*` が `.gitignore` 済み〔SEC-99〕

## セキュリティ — アプリケーション（A01 / A06 / A07 / A08）

- [ ] 認可のテストが主要エンドポイントに存在する〔SEC-05〕
- [ ] 次のすべてにレート制限がある: **ログイン / パスワードリセット / サインアップ /
      メール送信 / 課金 / 削除**〔SEC-40, SEC-41〕
- [ ] 書き込み系エンドポイントにサイズ上限・件数上限がある〔SEC-40〕
- [ ] ファイルアップロードがあるなら、MIME検証・サイズ上限・別ドメイン配信〔SEC-42〕
- [ ] Webhook の署名検証が有効（Stripe等）〔SEC-60〕
- [ ] **決済・課金確定・メール送信・Webhook受信に冪等キーがあり、二重実行テストが通る**〔SEC-84〕
- [ ] 決済の成否をサーバー側で確定している（クライアントの申告で判断していない）〔SEC-61〕

- [ ] **バージョン固定された**外部スクリプトに SRI がある
