# チェックリスト: 機能完成時（G2）

機能を1つ作り終えたら、これを上から通す。**1つでも欠けがあれば不合格**（実装継続）。

**このリストには「機械が判定できないもの」だけを載せる。**
`pnpm verify` が落とせるもの（型エラー、lint、フォーマット、`test.only` 残留、
`jsx-a11y` 警告、テストの失敗）は、緑であること自体が保証なので項目にしない
（[00-principles.md](../00-principles.md) P6）。

**[01-definition-of-done.md](../01-definition-of-done.md) G2 の MUST のうち、
`pnpm verify` で機械判定できないものを漏れなく含む。**
逆は不要 ── このリストにしかない項目は出典IDで規則本体に紐づいていればよい。
G2 を変更したら、同じPRでこのリストも更新すること。

**無印は MUST。SHOULD の項目には明示的に `(SHOULD)` と書く。**

コピーして使う。

---

## 0. 前提

- [ ] **`pnpm verify` が緑**（typecheck / lint / format / test / build。これで G1 は充足）
- [ ] デバッグコード・コメントアウトされた死んだコードを残していない

## 1. 仕様

- [ ] G0 で定義した Given / When / Then がすべて満たされている
- [ ] 満たせなかった条件がある場合、**明示して記録した**（黙って落としていない）
- [ ] 作った機能を1文で説明できる

## 2. 型

- [ ] 外部入力（フォーム / `searchParams` / `params` / ヘッダ / 外部API）が**境界でスキーマ検証**を通っている
- [ ] `as unknown as T` を使っていない
- [ ] 状態が判別可能なunionで表現され、**ありえない組み合わせが型として作れない**
- [ ] `@ts-expect-error` を使ったなら、理由コメントがある

## 3. 権限（最重要）

- [ ] データの読み書きが **`server-only` な DAL 関数**を経由している
- [ ] DAL の外で DB パッケージ / `process.env` を import していない
- [ ] DAL 関数の中で**認証**（誰か）を確認している
- [ ] DAL 関数の中で**認可**（このリソースの所有者か / 権限があるか）を確認している
- [ ] Server Action がページの `redirect()` に依存せず、**アクション経由でも認可が効く**
- [ ] クライアントに返るのが **DTO**（UIに必要なフィールドのみ）で、DBレコードそのままでない
- [ ] Client Component の props 型が広すぎない（`user: User` のようになっていない）
- [ ] Server Action の**戻り値**が最小限

## 4. テスト

- [ ] 純粋なビジネスロジックにユニットテストがある
- [ ] DAL / Server Action / Route Handler に統合テストがある
- [ ] **「他人のリソースを操作しようとすると失敗する」テスト**がある
- [ ] バリデーションの境界値・不正入力のテストがある
- [ ] （バグ修正なら）修正前に失敗する回帰テストを**先に**書いた
- [ ] クリティカルパスを変えたなら E2E を追加/更新した
- [ ] 追加したテストが単独実行でも通る（他のテストに依存していない）

## 5. 壊れ方

- [ ] loading の表示があり、**レイアウトが跳ねない**
- [ ] empty の表示があり、**次の行動への導線**がある
- [ ] error の表示に3要素がある: ①何が起きたか ②次に取れる操作 ③（想定外なら）エラーID
- [ ] エラー時にスタックトレース / SQL / 内部パスがユーザーに露出しない
- [ ] 認可・検証の失敗が「拒否」に倒れている（フォールバックで通していない）
- [ ] 外部API呼び出しにタイムアウトがある
- [ ] `catch` して握りつぶしていない（するなら理由コメント）
- [ ] **決済・課金確定・メール送信・Webhook受信に冪等キーがあり、二重実行テストがある**（SEC-84）

## 6. 観測

- [ ] 未捕捉例外がエラー監視に届く
- [ ] 重要な操作（作成 / 更新 / 削除 / 課金 / 認証）が構造化ログに残る
- [ ] ログとエラー監視に **パスワード / トークン / APIキー / 個人情報の本文が入っていない**

## 7. 戻せる

- [ ] 1コミット or 1PRで revert できる
- [ ] DBマイグレーションがあるなら**後方互換**（旧コードでも動く）
- [ ] **生成コードと lockfile を除く差分が400行以内**（超えているなら G0 に戻って分割する。例外なし）

## UIを変更した場合（追加）

- [ ] **Tabキーだけで一周した**（フォーカスが見える / 順序が視覚順と一致 / 罠にはまらない）
- [ ] フォーム項目に `<label>` が紐づいている（プレースホルダで代用していない）
- [ ] エラーメッセージが `aria-describedby` で入力欄に関連づいている
- [ ] 意味のある画像に代替テキスト / 装飾画像は `alt=""` / アイコンボタンに `aria-label`
- [ ] テキストのコントラスト比 4.5:1 以上
- [ ] タップ対象が 24×24px 以上
- [ ] sticky header にフォーカスが隠れない
- [ ] ドラッグ操作があるなら**ドラッグ以外の代替手段**がある
- [ ] 画像に width/height または aspect-ratio がある（CLS）
- [ ] **375px 幅で崩れない / 横スクロールしない**
- [ ] クリック可能な要素が `<button>` / `<a>`（`<div onClick>` でない）
- [ ] 確認ダイアログを置いたのは不可逆な操作（削除・解約・送金）のみ
- [ ] （クライアント遷移があるなら）遷移後に `<title>` が更新され、フォーカスが移る

## 外部サービス/依存/タグを追加した場合（追加）

- [ ] PR本文に **パッケージ名 / 週間DL数 / 最終公開日 / 直接依存数** を記載した（SEC-12）
- [ ] 最終公開日が12か月以上前、または週間DL数が1万未満なら、採用理由を書いた（SEC-12）
- [ ] 10行で書けるものに依存を足していない
- [ ] lockfile が更新され、コミットされている
- [ ] 解析/広告タグなら、**同じPRで外部送信の公表事項を更新した**（JP-03）
- [ ] `docs/third-party.md` を更新した
- [ ] サードパーティ `<script>` が合計3本を超えていない（SEC-62）
- [ ] バージョン固定された外部スクリプトなら SRI を付けた（可変配布物は対象外）（SEC-64）

## 個人情報を新たに扱う場合（追加）

- [ ] 何を / なぜ / どこに保存し / いつ消すか を説明できる
- [ ] **プライバシーポリシーの記載と実態が一致している**（同じPRで更新した）
- [ ] **アカウント削除時にこのデータがどうなるか**が決まっており、`docs/privacy-ops.md` に書いた（JP-02）
- [ ] 保存時の暗号化・アクセス制御がある
- [ ] 要配慮個人情報を取得していない
- [ ] (SHOULD) そもそも取らずに済ませられないか検討し、その結論を書いた〔JP-02〕
